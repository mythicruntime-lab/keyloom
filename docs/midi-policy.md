# MIDI import and managed-library policy

Keyloom accepts Standard MIDI Files (SMF) types 0 and 1 with metrical ticks. Type 2 and SMPTE division return explicit unsupported-format errors. Empty songs, truncated chunks/events, absent End-of-Track, zero PPQ/tempo, invalid signatures and inconsistent headers are rejected. Limits are 16 MiB, 256 tracks, 250,000 total events, 100,000 note onsets and 24 hours. Lazy event iteration enforces budgets before building large collections. These are safety bounds, not promises of smooth rendering at each bound.

Every note has a stable source-order ID. Parts are `(source track × 16) + zero-based channel`, so two source tracks on the same channel remain independently selectable. Playback uses a global tempo map; default tempo is 500,000 microseconds per quarter until overridden. Tempo events are sorted by tick, source track and source event; the last at a shared tick wins, with a warning. Default meter is 4/4. Notes and controllers retain source ticks and computed milliseconds.

Zero-velocity note-on is note-off. Overlapping equal pitches pair FIFO within each source track/channel. An unmatched release is ignored with a count in warnings. Missing releases close at their own track end, no earlier than one quarter note after onset, with a warning. A different track's release cannot close the note. Sustain CC64 is stored separately and does not change key-release time. Other controllers remain in the canonical controller list, but the basic piano-training tone does not reproduce general instrument programs, pitch bend, pressure or every controller. Channel 10 is percussion and defaults to accompaniment rather than a practice target. SysEx and device-configuration messages are never sent to a MIDI device. Original bytes preserve all source events for exact export.

The library lives under the application's user-data directory, outside the checkout. It stores exact source bytes in `midi/<sha256>.mid`, canonical song JSON, original source path, editable metadata and arrangement settings in SQLite. A successful import returns the same Ready entry used by list/search and direct Open; filters cannot invalidate that returned ID. Identical bytes produce one entry regardless of filename; different bytes always represent separate arrangements. Search covers title, artist, tags and arrangement, with Unicode lowercasing and literal substring matching. Source MIDI text is treated as untrusted plain text.

Import parses completely, writes a unique hash-named `.part` file, flushes it, renames it to the final managed name, then commits a Ready record using SQLite WAL and FULL synchronization. A failed or interrupted copy never appears in the Ready query. Startup removes hash-shaped partial/uncommitted files in the managed MIDI directory, completes pending managed deletions, and hides records whose managed copies are absent. It never scans external folders or reparses every song. Reimport can recover a missing managed file without discarding edited metadata or settings. Power-loss durability still depends on the Windows/filesystem/storage stack; no application can promise survival of failing storage.

Remove is a two-phase managed deletion so startup can finish an interrupted operation. The UI must explicitly confirm it. External originals are never moved, modified or removed. Export verifies the content hash and writes exact original bytes to a new destination only; an existing destination is refused. No destructive overwrite is needed to export a song.

Practice versions keep note removals separately from the original MIDI. Stable note/part IDs, original duration, controllers and tempo maps remain unchanged; only the version's note view and part note counts change. Each version has its own settings and metadata. Undo persists the last 100 removal actions across restarts. Saving another version copies the current note view but starts a fresh Undo history. A version with every note removed is valid even though importing an empty MIDI is not. Remove a practice version to delete only that version's record; originals with dependent versions cannot be removed. Edited MIDI export is deferred and rejected before any destination write. Keyboard-range warnings identify notes outside the configured range; they do not silently transpose or remove notes.

The generated fixtures are original test/demo material authored for this project. The opt-in 1,000-song test exercises actual managed copies, SQL transactions, filtering and loading; it prints observed timings without pretending a shared-machine performance target is a universal guarantee. Transport integration tests feed the imported canonical model into the real engine; this is simulated scheduling and does not verify a Yamaha keyboard, USB interface or audible native output.
