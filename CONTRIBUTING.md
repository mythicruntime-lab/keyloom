# Contributing to Keyloom

Thanks for helping. Keyloom is a small, offline Windows piano trainer, so changes are easiest to review when they are focused and say exactly what was tested.

## Ground rules

- **Offline and private.** No network calls, accounts, telemetry, cloud services or LLM features. Imported songs stay on the user's computer.
- **No third-party content.** Don't add commercial songs, samples, SoundFonts, fonts or artwork. Test MIDI should be generated by the test suite or written by you.
- **Originals are never changed.** Editing features work on practice versions; the imported MIDI and its library record stay byte-for-byte intact.
- **Say what was physically tested.** Simulated input and successful MIDI sends don't prove that keys were played, lit or heard. Keep that distinction in pull requests and docs, as [docs/test-report.md](docs/test-report.md) does.

Check the [roadmap](ROADMAP.md) before starting something large; several features are deliberately deferred.

## Set up

You need Windows 11 x64, Node 24 (`.nvmrc`), rustup, Visual Studio 2022 C++ Build Tools with the Windows SDK, and the WebView2 runtime. `rust-toolchain.toml` pins Rust 1.98.0; rustup installs it on first use.

```powershell
powershell -File scripts/Build.ps1 -Mode restore
powershell -File scripts/Build.ps1 -Mode dev
```

`Build.ps1` uses two Cargo workers by default; pass `-Jobs` to change that.

## Before opening a pull request

Run the same checks as [GitHub Actions](.github/workflows/check.yml):

```powershell
npm run check
npm run format:check
npm run build
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
cargo clippy --manifest-path src-tauri/Cargo.toml --locked --all-targets --features custom-protocol -- -D warnings
cargo test --manifest-path src-tauri/Cargo.toml --locked --features custom-protocol
```

`npm run build` must come before the Cargo commands, because the `custom-protocol` feature embeds `dist/`. Format frontend code with `npm run format` and Rust code with `cargo fmt --manifest-path src-tauri/Cargo.toml`.

Add or update tests with the change. The Rust suite covers the parser, library, transport and export; behavior that only shows up in the real window belongs in the native smoke test (`src/smoke.ts`).

## Changing dependencies

Every dependency's license text is kept in `licenses/` and shipped with each package. After any change to `package-lock.json`, `Cargo.lock`, the Rust toolchain or the installer:

```powershell
cargo fetch --manifest-path src-tauri/Cargo.toml --locked
node scripts/audit-licenses.mjs
```

Commit the regenerated files under `licenses/`. The audit exits with code 2 when a selected package lacks a reviewed license or preserved text. New license types also need a note in [docs/dependencies.md](docs/dependencies.md). Avoid adding dependencies when a small amount of project code will do.

## Native and hardware checks

After `Build.ps1 -Mode package`, the native smoke test drives the real window with an isolated library. Close any running Keyloom first.

```powershell
powershell -File scripts/Native-Smoke.ps1 -Device 'USB MIDI Interface'
```

Use your own MIDI input's name. Adding `-OutputDevice` also sends real Light Guide notes, which can sound or light the keyboard. For changes to MIDI input, audio, matching or Light Guide, also run the relevant items in the [hardware checklist](docs/hardware-checklist.md) and list them in the pull request with your keyboard, interface and date.

## Pull requests

- Keep each pull request to one change, and describe what it does for someone practicing.
- Note anything you couldn't verify, such as no keyboard available or Light Guide not observed.
- Update `CHANGELOG.md` for user-visible changes and the README when behavior changes.
- Project text files use LF line endings (`.gitattributes` enforces this); third-party files under `licenses/` keep their exact bytes.

## Reporting bugs

Use the **Bug report** issue form. Include your keyboard and MIDI interface, and don't attach copyrighted MIDI files; describe the file instead or attach one you made. Report security problems privately as described in [SECURITY.md](SECURITY.md), not in an issue.
